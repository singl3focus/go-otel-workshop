# Как участвовать в проекте

[English](CONTRIBUTING.md) | [Русский](CONTRIBUTING.ru.md)

Английская версия — оригинал. Русский перевод поддерживается рядом с ней.

Помогайте изучать трассировку: добавляйте небольшие запускаемые примеры,
понятные объяснения, сообщения об ошибках и исправления перевода.

## Локальные проверки

Каждый каталог с номером — отдельный Go-модуль. Из его каталога:

```sh
go build -mod=readonly ./...
go test -mod=readonly -count=1 -timeout=60s -tags=solution ./...
```

На платформе с C toolchain запустите также race detector:

```sh
go test -mod=readonly -race -count=1 -timeout=60s -tags=solution ./...
```

Обычные тесты упражнений падают, пока участник их не исправил. Не подменяйте
`exercise.go` готовыми ответами ради зелёного теста. `-tags=solution` выбирает
эталон; этот путь проверяет CI. Меняя упражнение, убедитесь, что исходная
версия по-прежнему демонстрирует нужную ошибку, а эталон проходит те же проверки.

Из корня репозитория проверьте документацию:

```sh
python scripts/check_docs.py
```

Скрипт проверяет локальные Markdown-пути, якоря заголовков, переключение языков
и совпадение исполняемых блоков кода в парных README. Внешние ссылки и смысловую
точность перевода он не проверяет. CI запускает его на Linux из чистой копии.

Форматируйте изменённые Go-файлы через `gofmt`. Корневой `.golangci.yml` —
дополнительный локальный инструмент: из каждого Go-модуля можно запустить
`golangci-lint run --config ../.golangci.yml`. В конфигурации включены исправления:
проверяйте получившийся diff. Этот линтер не входит в набор проверок CI.

## Английский оригинал и русский перевод

- `README.md` — английский оригинал, `README.ru.md` — его русский перевод.
- Держите переключатель языка в начале и ведите русскую навигацию к русским файлам.
- Обновляйте обе версии в одном pull request при изменении команд, требований,
  порядка уроков и ожидаемых результатов. Исполняемые блоки кода должны совпадать.
- В общем исходном коде пишите английское объяснение и затем русское (`EN:`/`RU:`).
  Не меняйте build tags, директивы линтера, идентификаторы, имена спанов и ключи атрибутов.
- Диагностика упражнений должна объяснять ошибку на обоих языках. Технические поля
  `TraceID`, `SpanID`, `got`, `want` не требуют перевода идентификаторов.
- Сохраняйте технический смысл. Объясняйте реальное расхождение вместо буквального
  воспроизведения ошибочного утверждения на любом из языков.

## Полезный новый урок

Задайте одну учебную цель, точную команду, наблюдаемые свойства трассы и отличие
от соседних уроков. Если тема не требует бэкенда, предпочитайте stdout и тестовые
серверы внутри процесса. Указывайте порты и внешние сервисы. Для упражнения
нужны `problem.go`, исходно сломанный `exercise.go`, тесты и `solution.go` под тегом.

Сохраняйте небольшой объём демонстраций. Отличайте намеренные антипаттерны
от дефектов эталона. Не утверждайте, что «все ошибки попадут в sampling»
или «таймаут остановит всю работу», если пример этого не подтверждает.

В pull request опишите проблему, поведение для участника и выполненные команды.
Issues и обсуждение могут быть на английском или русском.
Обсуждайте конкретную работу и уважайте собеседников.
