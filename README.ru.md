# OpenTelemetry для Go: практический воркшоп

[English](README.md) | [Русский](README.ru.md)

Английская версия — оригинал. Русский перевод поддерживается рядом с ней.

Изучайте распределённую трассировку на небольших Go-программах: запускайте
примеры, наблюдайте разрывы trace context и исправляйте инструментирование.
От одного спана в терминале перейдите к HTTP-запросам, фоновым задачам,
воркерам и вызовам между сервисами.

Достаточно знать Go, `context.Context` и `net/http`. Сейчас воркшоп посвящён
**трассировке**; пайплайны метрик и логов в его объём не входят.

## Первый спан

Установите Go **1.25.1 или новее**. В модулях закреплены OTel SDK **1.43.0**
и, где он используется, `otelhttp` **0.68.0**. Первый запуск скачивает зависимости Go.

```sh
git clone https://github.com/singl3focus/go-otel-workshop.git
cd go-otel-workshop/00-otel-basics/01-minimal
go run .
```

В терминале появится JSON спана `hello`: `TraceID`, `SpanID`, время начала
и завершения. Идентификаторы и время при каждом запуске меняются.
Для первого примера Docker и бэкенд наблюдаемости не нужны.

## Упражнения и эталоны

Из корня репозитория:

```sh
cd 02-base-issues/missing-span-end
go run .
go test .
```

Тест упражнения **изначально падает**. Исправьте `exercise.go`, повторите тест,
потом сравните с `solution.go`. `problem.go` остаётся отдельной демонстрацией
ошибки: исправление упражнения не меняет поведение `go run .`.

Для проверки эталона без изменения собственного ответа:

```sh
go test -tags=solution .
```

Тег `solution` выбирает `solution.go` вместо `exercise.go`. Так устроены
четыре упражнения модуля 02 и упражнение модуля 05.

## HTTP-примеры и экспорт

Модули 00, 02, 03, 04 и 05 экспортируют спаны в stdout. Модуль 01 использует
**OTLP/gRPC**: в модуле два приложения и закреплённый
[Compose-стенд Collector + Jaeger](01-local-observability-stack/stack/README.ru.md).
Адрес по умолчанию — `http://localhost:4317`, как у локального Collector.
Есть команды готовности и тестов реального бэкенда; живой запуск ещё предстоит.
Для другого receiver задайте `OTEL_EXPORTER_OTLP_ENDPOINT`.

В [модуле 01](01-local-observability-stack/README.ru.md) есть команды для разных
оболочек, в [диагностике](docs/troubleshooting.ru.md) — разбор пропавших спанов.
Большинство HTTP-примеров занимает порт 8080, модуль 05 также занимает 8081.
Запускайте их по одному.

## Проверки и участие

В любом модуле `go build ./...` проверяет сборку, а
`go test -tags=solution ./...` запускает тесты на эталонных решениях.
Обычный `go test ./...` в нерешённых упражнениях падает намеренно.
[CI](.github/workflows/ci.yml) собирает и тестирует все модули и проверяет ссылки
документации. Локальная проверка не подтверждает доставку OTLP.

Нашли непонятное объяснение или хотите добавить сценарий? См.
[правила участия](CONTRIBUTING.ru.md) и [план развития](ROADMAP.ru.md).
Все README доступны на английском и русском; комментарии к коду и диагностика
упражнений содержат оба языка. Обновляйте обе версии в одном изменении.
